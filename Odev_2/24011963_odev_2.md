# Git ve GitHub Kullanımı

## 1. Giriş

Yazılım geliştirirken bir proje üzerinde sürekli değişiklikler yapılır. Yeni özellikler eklenebilir, mevcut kodlar düzenlenebilir veya bazı hatalar giderilebilir. Ancak bu değişiklikleri düzenli bir şekilde takip etmek ve gerektiğinde önceki sürümlere geri dönebilmek önemlidir. Özellikle birden fazla kişinin aynı proje üzerinde çalıştığı durumlarda bu süreci yönetmek daha da zorlaşabilir.

Git ve GitHub, bu tür durumları daha kolay yönetmek için kullanılan araçlardır. Bu çalışmada Git ve GitHub'ın temel kullanım amaçları incelenmiş, sık kullanılan kavramlar açıklanmış ve bu kavramların nasıl kullanıldığı örneklerle gösterilmiştir.

## 2. Git Nedir?

Git, yazılım projelerinde yapılan değişiklikleri takip etmeye yarayan bir versiyon kontrol sistemidir (Version Control System). Bir proje üzerinde zaman içerisinde yapılan değişiklikleri kaydeder ve bu kayıtlar sayesinde projenin önceki sürümlerine dönülmesine imkân sağlar.

Örneğin bir program üzerinde çalışırken daha önce doğru çalışan bir kodu yanlışlıkla değiştirdiğimizi düşünelim. Git kullanıldığında önceki kayıtlar incelenebilir ve gerektiğinde eski sürüme geri dönülebilir. Böylece her değişiklikten sonra dosyaların farklı kopyalarını oluşturmak zorunda kalmayız.

Git'in önemli özelliklerinden biri de internet bağlantısı olmadan yerel bilgisayarda kullanılabilmesidir. Proje üzerindeki değişiklikler öncelikle bilgisayarda takip edilir, daha sonra istenirse GitHub gibi platformlara gönderilir.

## 3. GitHub Nedir?

GitHub, Git kullanılarak yönetilen projelerin internet üzerinde saklanmasını, paylaşılmasını ve ekip halinde geliştirilmesini sağlayan bir platformdur.

Git ile GitHub aynı şey değildir. Git, değişiklikleri takip eden versiyon kontrol sistemidir. GitHub ise Git projelerinin çevrim içi ortamda barındırılmasını ve diğer geliştiricilerle paylaşılmasını sağlar.

Örneğin bilgisayarımızda Git kullanarak bir proje oluşturabiliriz. Daha sonra bu projeyi GitHub'a yükleyerek internet üzerinden erişilebilir hâle getirebiliriz. Bir ekip içerisinde çalışan kişiler de aynı repository üzerinden projeye katkıda bulunabilir.

## 4. Repository (Depo)

Repository, bir projeye ait dosyaların ve bu dosyalarda yapılan değişikliklerin geçmişinin tutulduğu depodur. Kısaca bir yazılım projesinin saklandığı ve yönetildiği alandır.

GitHub üzerinde yeni bir proje oluşturulurken bir repository açılır. Repository içerisinde kaynak kodları, dokümantasyon dosyaları, görseller ve projeyle ilgili diğer dosyalar bulunabilir.

Repository'ler Public veya Private olarak oluşturulabilir:

- **Public:** Herkes repository içeriğini görüntüleyebilir.
- **Private:** Repository içeriğine yalnızca izin verilen kişiler erişebilir.

Örneğin bu ödev kapsamında GitHub üzerinde `ad_soyad_YODA_IHA_YAZILIM` isminde bir repository oluşturulmuştur. Bu repository içerisinde farklı ödevlere ait dosyaların ayrı klasörlerde tutulması planlanmıştır.

Bir Git repository'si oluşturmak için terminalde aşağıdaki komut kullanılabilir:

git init


Bu komut, bulunulan klasörü Git tarafından takip edilebilen bir repository hâline getirir.

## 5. Commit

Commit, proje üzerinde yapılan değişikliklerin belirli bir noktada kaydedilmesini sağlar. Her commit, yapılan değişiklikleri açıklayan bir mesajla birlikte oluşturulur. Bu mesaj sayesinde daha sonra hangi değişikliklerin ne amaçla yapıldığı anlaşılabilir.

Commit oluşturulmadan önce değişikliklerin Stage alanına eklenmesi gerekir. Bu sayede hangi dosyaların kaydedileceği belirlenir.

Örneğin bir programdaki hatayı düzelttiğimizi düşünelim. Bu değişikliği commit ederek projenin geçmişine kaydedebiliriz.

Kullanılan temel komutlar:


git add .
git commit -m "Hata duzeltildi"


İlk komut, mevcut klasördeki değişiklikleri Stage alanına ekler. İkinci komut ise Stage alanındaki değişiklikleri bir commit olarak kaydeder.

Commit mesajlarının yapılan işlemi açıkça anlatması önemlidir. Örneğin `Dosya eklendi`, `Giris hatasi duzeltildi` veya `Yeni fonksiyon eklendi` gibi mesajlar kullanılabilir.

Commit işlemi değişiklikleri yerel repository'ye kaydeder. Bu işlem tek başına dosyaları GitHub'a göndermez.

## 6. Branch (Dal)

Branch, bir projenin ana sürümünü doğrudan etkilemeden farklı çalışmalar yapılmasına imkân sağlayan geliştirme dalıdır.

Özellikle ekip çalışmalarında oldukça kullanışlıdır. Çünkü her geliştirici farklı bir özellik üzerinde kendi branch'inde çalışabilir. Böylece bir kişinin yaptığı değişiklikler, diğer kişilerin çalışmalarını doğrudan etkilemez.

Genellikle projenin ana dalı `main` olarak adlandırılır. Yeni bir çalışma yapılacağı zaman `main` üzerinden ayrı bir branch oluşturulabilir.

Branch oluşturmak için:


git branch odev_2


Oluşturulan branch'e geçmek için:


git switch odev_2


Branch oluşturma ve geçme işlemleri tek komutla da yapılabilir:

git switch -c odev_2

Mevcut branch'leri görüntülemek için:

git branch


Bu ödevde de ikinci ödevin dosyalarını ana projeden ayrı geliştirmek amacıyla `odev_2` isimli bir branch oluşturulmuştur. Çalışmalar bu branch üzerinde tamamlandıktan sonra ana branch'e aktarılmıştır.

## 7. Stage (Hazırlık Alanı)

Stage, yapılan değişikliklerin commit işlemine hazırlanmak üzere seçildiği alandır. Bir dosyada değişiklik yapmak, o değişikliğin otomatik olarak commit edileceği anlamına gelmez. Öncelikle hangi değişikliklerin kaydedileceğinin belirlenmesi gerekir.

Bu işlem Stage alanı üzerinden gerçekleştirilir.

Örneğin bir projede üç farklı dosyada değişiklik yaptığımızı düşünelim. Bunlardan yalnızca ikisini kaydetmek istiyorsak sadece o dosyaları Stage alanına ekleyebiliriz.

Tüm değişiklikleri Stage alanına eklemek için:

git add .

Yalnızca belirli bir dosyayı eklemek için:

git add dosya_adi.c

Stage alanına eklenen dosyaları görüntülemek için:

git status

Stage işlemi, commit işleminden önce hangi değişikliklerin kaydedileceğini kontrol etmemizi sağlar. Böylece henüz tamamlanmamış veya kaydedilmesi istenmeyen değişiklikler commit içerisine dahil edilmez.

## 8. Merge (Birleştirme)

Merge, farklı branch'lerde yapılan değişikliklerin birleştirilmesini sağlayan işlemdir. Genellikle ayrı bir branch üzerinde tamamlanan çalışmaların ana branch'e aktarılması için kullanılır.

Örneğin bir projede yeni bir özellik geliştirmek için `ozellik` isimli bir branch oluşturduğumuzu düşünelim. Bu branch üzerinde çalışmalar tamamlandığında yapılan değişiklikleri `main` branch'ine aktarabiliriz.

Öncelikle ana branch'e geçilir:

git switch main

Daha sonra diğer branch birleştirilir:

git merge odev_2


Bu işlem sonucunda `odev_2` branch'indeki commit'ler ve değişiklikler `main` branch'ine aktarılır.

GitHub üzerinde bu işlem Pull Request (PR) aracılığıyla da gerçekleştirilebilir. Pull Request, bir branch'te yapılan değişikliklerin başka bir branch'e aktarılmasını talep etmek ve bu değişiklikleri incelemek için kullanılan bir özelliktir. Değişiklikler incelendikten sonra Merge işlemi onaylanabilir.

Bu ödevde `odev_2` branch'i üzerinde hazırlanan dokümantasyon tamamlandıktan sonra Pull Request oluşturulmuş ve değişiklikler `main` branch'ine merge edilmiştir.

## 9. Push

Push, yerel bilgisayardaki repository içerisinde bulunan commit'lerin uzak repository'ye (Remote Repository) gönderilmesini sağlar.

Örneğin bilgisayarımızda bir proje üzerinde çalışıp birkaç commit oluşturduğumuzu düşünelim. Bu commit'leri GitHub'daki repository'ye göndermek için push komutunu kullanırız.

Temel kullanım şekli:

git push origin main

Burada `origin`, uzak repository'nin varsayılan adıdır. `main` ise değişikliklerin gönderileceği branch'i belirtir.

Yeni oluşturulan bir branch ilk kez GitHub'a gönderilirken şu komut kullanılabilir:

git push -u origin odev_2

Push işlemi sayesinde yerel bilgisayarda kaydedilen çalışmalar GitHub üzerinde de saklanır. Böylece projeye farklı cihazlardan veya ekip üyeleriyle birlikte erişmek mümkün olur.

## 10. Pull

Pull, uzak repository'de bulunan değişikliklerin yerel bilgisayardaki repository'ye alınmasını sağlar. Özellikle ekip çalışmalarında diğer kişilerin yaptığı değişiklikleri güncel olarak takip etmek için kullanılır.

Örneğin bir ekip arkadaşımız GitHub'daki `main` branch'ine yeni bir dosya eklemiş olsun. Kendi bilgisayarımızdaki projeyi bu değişikliklerle güncellemek için pull komutunu kullanabiliriz.

Temel kullanım şekli:

git pull origin main

Bu komut, GitHub'daki `main` branch'inde bulunan yeni değişiklikleri yerel bilgisayardaki mevcut branch'e getirir ve birleştirir.

Pull işlemi genel olarak iki aşamadan oluşur:

- **Fetch:** Uzak repository'deki yeni değişiklikleri indirir.
- **Merge:** İndirilen değişiklikleri mevcut yerel branch ile birleştirir.

Bu nedenle pull komutu, yalnızca dosyaları indirmekten farklı olarak yerel projeyi uzak repository'deki değişikliklerle günceller.

## 11. Sonuç

Bu çalışma sırasında Git ve GitHub'ın yazılım geliştirme sürecindeki kullanım amaçları ve temel özellikleri incelenmiştir. Repository, commit, branch, stage, merge, push ve pull gibi kavramların ne anlama geldiği ve hangi durumlarda kullanıldığı öğrenilmiştir.

Özellikle branch kullanımı sayesinde bir projenin farklı bölümlerinin birbirinden bağımsız geliştirilebildiği, merge işlemiyle de tamamlanan çalışmaların ana projeye aktarılabildiği görülmüştür.

Yapılan uygulama kapsamında GitHub üzerinde bir repository oluşturulmuş, ikinci ödev için ayrı bir branch açılmış, dokümantasyon bu branch üzerinde hazırlanmış ve daha sonra `main` branch'i ile birleştirilmiştir. Bu işlemler sayesinde Git ve GitHub'ın yalnızca teorik olarak değil, gerçek bir çalışma üzerinde nasıl kullanıldığı da deneyimlenmiştir.






# İHA Masterclass – Eğitim Özeti

## 1. Video – İHA Masterclass Eğitimine Giriş

Bu eğitimde İHA'ların hem donanım hem de yazılım tarafını öğrenerek çalışan bir sistem hâline getirilmesi amaçlanıyor. Eğitim boyunca motorlar, uçuş kontrol kartları, sensörler, görev bilgisayarları ve haberleşme sistemleri gibi temel bileşenler ele alınıyor.

Yazılım tarafında ise ArduPilot ve PX4 gibi otopilot yazılımları, görev bilgisayarlarında kullanılan ROS 2 ve simülasyon ortamları üzerinde duruluyor. Gazebo Harmonic kullanılarak İHA'ların gerçek uçuş öncesinde simüle edilmesi planlanıyor. Bunun yanında Ubuntu ortamının sanal makine veya WSL üzerinden kurulması gibi hazırlık konuları da bulunuyor.

Yer kontrol istasyonu yazılımları olan Mission Planner ve QGroundControl üzerinden İHA'nın kontrol edilmesi, görev planlaması ve parametre ayarlarının yapılması gösteriliyor. İlerleyen aşamalarda görüntü işleme, nesne tespiti, yapay zekâ modellerinin eğitilmesi ve bu modellerin görev bilgisayarlarında çalıştırılması ele alınıyor.

Eğitimin devamında simülasyon ortamında farklı İHA'ların birlikte çalışması, uçuş kayıtlarının incelenmesi ve gerçek multikopter ile sabit kanatlı araçların uçuş testlerinin yapılması hedefleniyor. Böylece teorik olarak öğrenilen bilgilerin gerçek bir İHA sistemi üzerinde uygulanması amaçlanıyor.

## 2. Video – İHA Kullanım Alanları, Türleri ve Çalışma Prensipleri

İHA'lar günümüzde birçok farklı alanda kullanılabiliyor. Videoda kargo taşımacılığı, bina dış cephelerinin temizlenmesi, haritalama, üç boyutlu model oluşturma ve arama-kurtarma çalışmaları gibi örnekler veriliyor. Kullanım amacına göre farklı İHA türleri tercih ediliyor.

Temel olarak İHA'lar multikopter ve sabit kanatlı olmak üzere iki ana grupta inceleniyor.

**Multikopterler**, birden fazla motor ve pervane sayesinde havada kalabilen araçlardır. Trikopter, quadcopter, hexacopter ve octocopter gibi çeşitleri bulunur. Motor sayısı arttıkça üretilebilen toplam itki ve taşıma kapasitesi de artabilir. Ancak motor sayısının artması ağırlığı ve enerji tüketimini de etkiler. X8 ve Y6 gibi motor yerleşimleri de bu grupta kullanılan farklı tasarımlardır.

İHA seçiminde itki/ağırlık oranı önemlidir. Videoda örnek olarak 3 kg ağırlığındaki bir aracın toplam 6 kg itki üretebilmesi, yaklaşık 2:1 itki/ağırlık oranı üzerinden açıklanıyor. Bu oran, aracın ağırlığına kıyasla ne kadar itki üretebildiğini anlamamıza yardımcı olur.

**Sabit kanatlı İHA'lar** ise uçuş sırasında kanatları sayesinde kaldırma kuvveti oluşturur. Multikopterlere göre daha uzun mesafelerde uçuş gerçekleştirebilirler. Ancak kalkış ve inişleri daha fazla alan ve planlama gerektirir. Motorlar aracın önünde, arkasında veya farklı yerleşimlerde bulunabilir.

Bu iki tasarımın özelliklerini birleştiren VTOL sistemleri de vardır. VTOL tasarımlarında dikey kalkış ve iniş için kullanılan motorlar ile ileri uçuşu sağlayan motorlar birlikte bulunabilir. Tilt-rotor sistemlerinde ise motorların yönü değiştirilerek dikey ve yatay uçuş arasında geçiş yapılır.

Uçuş kontrol yazılımında doğru hava aracı tipinin seçilmesi önemlidir. Çünkü motorların ve kontrol yüzeylerinin yerleşimi, aracın nasıl yönetileceğini etkiler. Bu nedenle genellikle yazılımda hazır hava aracı konfigürasyonları kullanılır.

## 3. Video – İHA'ların Çalışma Prensipleri ve Uçuş Kontrol Mekanizması

Bir İHA'nın havalanabilmesi için motorların oluşturduğu toplam itkinin aracın ağırlığından büyük olması gerekir. Motorların ürettiği itki, kullanılan bataryanın voltajına ve pervanenin özelliklerine göre değişebilir. Motorların eşit itki üretmesi aracın dengeli durmasına yardımcı olur.

Multikopterlerde hareket, motorların dönüş hızlarının birbirinden farklı ayarlanmasıyla sağlanır. Üç temel hareket bulunur:

- **Roll:** Aracın sağa veya sola yatmasıdır.
- **Pitch:** Aracın burnunun öne veya arkaya eğilmesidir.
- **Yaw:** Aracın dikey eksen etrafında dönmesidir.

Örneğin aracın öne doğru hareket etmesi için arka motorların itkisi artırılırken ön motorların itkisi azaltılır. Sağa veya sola yatma hareketinde de motorların bulunduğu taraflara göre itki farklılaştırılır. Yaw hareketinde ise motorların dönüş yönlerinden kaynaklanan tork farkından yararlanılır. Birbirine zıt yönde dönen motorlar, oluşan dönme etkilerinin dengelenmesine yardımcı olur.

Aracın ağırlık merkezinin doğru konumlandırılması da uçuş dengesi açısından önemlidir. Ağırlık merkezi kaydığında uçuş kontrolcüsü motorların itkilerini değiştirerek bu dengesizliği telafi etmeye çalışır.

Sabit kanatlı İHA'larda ise kaldırma kuvveti kanatlar sayesinde oluşur. Videoda kanadın üst ve alt yüzeyleri arasındaki hava akışı farkının bu kaldırma kuvvetini oluşturduğu açıklanıyor. Böylece sabit kanatlı araçlar ileri hareket ederek havada kalabilir.

## 4. Video – İHA'ların Temel Bileşenleri ve Motorların Çalışma Prensibi

İHA sisteminde her bileşenin farklı bir görevi bulunur. Görev bilgisayarı (Companion Computer), Raspberry Pi veya Jetson gibi sistemler üzerinden çalışır. Görüntü işleme ve farklı hesaplamalar gibi işlemleri gerçekleştirir. Bu işlemlerin doğrudan araç üzerinde yapılması, yer istasyonundan gelecek komutları beklemeye göre daha hızlı karar alınmasını sağlar.

Telemetri, İHA ile yer kontrol istasyonu arasındaki haberleşmeyi sağlar. GPS aracın konumunu belirlerken airspeed sensörü özellikle sabit kanatlı araçlarda hava hızını ölçer. Kamera ise görüntü elde etmek için kullanılır ve görev bilgisayarına bağlanabilir.

Uçuş kontrolcüsü (Flight Controller), sistemin temel yönetim merkezidir. Sensörlerden gelen verileri işler ve verilen komutları motorlara veya kontrol yüzeylerine uygulanacak hareketlere dönüştürür. Örneğin belirli bir konuma gitme komutu verildiğinde bu hareketin nasıl gerçekleştirileceğini uçuş kontrolcüsü yönetir. Görev bilgisayarından farklı olarak temel sorumluluğu aracın uçuşunu kontrol etmek ve dengede tutmaktır.

Motor seçiminde dikkat edilmesi gereken özelliklerden biri motorun fiziksel boyutudur. Örneğin 2212 ifadesinde ilk iki rakam motorun stator çapını, son iki rakam ise yüksekliğini milimetre cinsinden belirtir. KV değeri ise motorun yüksüz durumda volt başına yaklaşık kaç devir yapabildiğini gösterir. Yüksek KV değerinin her zaman daha iyi performans anlamına gelmediği, seçim yapılırken verimliliğin de dikkate alınması gerektiği anlatılıyor.

## 5. Video – ESC, Uçuş Kontrolcüsü ve İHA Sensörleri

ESC (Electronic Speed Controller), uçuş kontrolcüsünden aldığı sinyallere göre motorların hızını düzenler. Motorla üç faz kablosu üzerinden bağlantı kurar ve motora gönderilen akımı kontrol eder.

Bataryadan gelen gücün birden fazla ESC'ye dağıtılması için PDB (Power Distribution Board) kullanılır. Power Module ise bataryanın voltaj ve anlık akım gibi bilgilerini uçuş kontrolcüsüne aktarır. Böylece operatör bataryanın durumunu takip edebilir.

Motor seçerken batarya voltajı, pervane boyutu, üretilecek itki, çekilecek akım ve verimlilik birlikte değerlendirilmelidir. ESC seçerken de motorun maksimum akım değerinden daha yüksek kapasiteli bir ESC tercih edilmelidir. Örneğin maksimum 10 A akım çeken bir motor için 15–20 A kapasiteli ESC seçilmesi, sistemin güvenli çalışması açısından önemlidir.

Uçuş kontrolcüsü, sensörlerden gelen bilgileri işleyerek aracın dengesini, yönünü ve hareketlerini yönetir. İşlemci hızı ve sensör sayısı, kontrolcünün seçiminde dikkat edilen özelliklerdir. Bazı uçuş kontrolcülerinde birden fazla IMU bulunur. Bunun amacı sensörlerden gelen verileri karşılaştırarak hatalı ölçümlerin etkisini azaltmaktır.

İHA'larda farklı amaçlarla kullanılan sensörler vardır. IMU aracın ivmesini ve dönüş hareketlerini ölçer. GPS konum bilgisini sağlar. Barometre irtifayı tahmin etmekte, manyetometre yön bilgisinin belirlenmesinde kullanılmaktadır. LiDAR ise mesafe ölçümü yaparak haritalama ve yerden yüksekliği belirleme gibi görevlerde kullanılabilir.

Sensörlerden gelen verilerin değerlendirilmesinde PID kontrolü önemli bir yere sahiptir. PID üç bölümden oluşur:

- **Proportional (P):** O anki hataya göre tepki oluşturur.
- **Integral (I):** Zaman içinde biriken hatayı azaltmayı amaçlar.
- **Derivative (D):** Hatanın değişim hızını dikkate alır.

Her İHA'nın motorları, ağırlığı ve tasarımı farklı olduğundan PID değerleri de araca uygun şekilde ayarlanmalıdır. Yanlış değerler aracın aşırı tepki vermesine ve dengesiz uçmasına neden olabilir.

GPS konum belirlemenin yanında Return to Home gibi işlevlerde de kullanılır. RTK sistemi ise GPS'in konum doğruluğunu artırmak için kullanılır. Sabit bir referans istasyonundan alınan düzeltme bilgileri sayesinde konum hatası azaltılabilir.

İHA üzerinde GPS, IMU, barometre ve diğer sensörlerden gelen verilerin birlikte değerlendirilmesine sensör füzyonu denir. Videoda bu işlem için EKF (Extended Kalman Filter) algoritmasından bahsediliyor. Bu algoritma, farklı sensörlerden gelen verileri değerlendirerek aracın konumu ve yönelimi hakkında daha doğru tahminler elde edilmesini sağlar.

Son olarak telemetri, İHA ile yer istasyonu arasındaki haberleşmeyi gerçekleştirir. Telemetri seçerken menzil, sinyal gücü ve haberleşme güvenilirliği önemlidir. Özellikle uzun mesafeli operasyonlarda güvenli ve kesintisiz haberleşme sağlanması gerekir.

## 6. Video – Görüntü Aktarımı, Görev Bilgisayarları ve Yer Kontrol İstasyonları

İHA üzerindeki kameradan alınan görüntüler yer istasyonuna veya görev bilgisayarına aktarılabilir. Yer istasyonuna aktarılan görüntü sayesinde pilot, aracın kamerasından gördüğü alanı canlı olarak takip edebilir. FPV sistemlerinde kullanılan gözlükler sayesinde pilot, İHA'nın bakış açısından görüntü alarak manuel kontrolü daha rahat gerçekleştirebilir.

Görüntü aktarımında analog ve dijital olmak üzere iki temel sistem bulunur. Analog sistemler daha düşük maliyetlidir ve hızlı görüntü aktarımı sağlar, ancak görüntü kalitesi dijital sistemlere göre daha düşüktür. Dijital sistemler ise daha yüksek çözünürlüklü görüntüler sunar. Videoda DJI sistemleri, dijital görüntü aktarımına örnek olarak gösteriliyor.

Görev bilgisayarı (Companion Computer), uçuş kontrolcüsünden farklı olarak görüntü işleme, yapay zekâ modelleri ve karmaşık hesaplamalar gibi işlemleri gerçekleştirir. Raspberry Pi ve NVIDIA Jetson bu amaçla kullanılan sistemler arasındadır. Özellikle Jetson Orin gibi cihazlar, görüntü işleme ve derin öğrenme modellerini daha yüksek FPS değerlerinde çalıştırabilir. FPS arttıkça sistem saniyede daha fazla görüntü karesi işleyebilir.

Kameradan alınan görüntü görev bilgisayarında işlenebilir ve nesne tespiti gibi işlemler gerçekleştirilebilir. Görev bilgisayarı elde ettiği sonuçları uçuş kontrolcüsüne ileterek aracın hareketlerini yönlendirebilir. Böylece görüntü işleme ve uçuş kontrolü birlikte çalışır.

Yer kontrol istasyonu (Ground Control Station), İHA operasyonlarının yönetildiği merkezdir. Operatör burada uçuş rotasını önceden planlayabilir, kalkış ve iniş noktalarını belirleyebilir ve aracın uçuş parametrelerini takip edebilir. Ayrıca canlı kamera görüntüleri izlenebilir, acil durumlarda aracın aldığı kararlar incelenebilir ve uçuş kayıtları (loglar) daha sonra analiz edilebilir.

Görev bilgisayarı ile yer istasyonu arasında Wi-Fi veya mobil veri üzerinden bağlantı kurulabilir. Bu sayede görev bilgisayarına bağlı kameradan alınan görüntüler yer istasyonuna aktarılabilir. SSH gibi yöntemlerle görev bilgisayarına uzaktan erişim de sağlanabilir.

Videoda yer kontrol istasyonlarının açık kaynaklı olabileceği de belirtiliyor. Bu sayede mevcut yazılımın kodları değiştirilerek ihtiyaca uygun yeni özellikler eklenebilir ve kişiselleştirilmiş bir yer kontrol istasyonu geliştirilebilir.

## 7. Video – Otopilot Yazılımları ve Uçuş Modları

Bu bölümde eğitim, İHA'ların donanımından yazılım tarafına geçiyor. Özellikle ArduPilot ve PX4 gibi otopilot yazılımlarının görevleri, aralarındaki farklar ve uçuş modları ele alınıyor.

Otopilot yazılımlarının temel görevlerinden biri sensör füzyonudur. GPS, IMU, LiDAR ve barometre gibi sensörlerden gelen veriler işlenerek aracın konumu, yönü ve hızı tahmin edilir. Buna state estimation denir. Uçuş kontrolü sayesinde yer istasyonundan veya görev bilgisayarından gelen komutlar motorlara ve kontrol yüzeylerine uygulanacak hareketlere dönüştürülür.

Bir diğer görev mission management, yani görev yönetimidir. Önceden yer istasyonunda hazırlanan uçuş planı otopilot yazılımına aktarılır. Böylece araç kalkıştan başlayarak belirlenen noktaları takip edebilir ve planlanan inişi gerçekleştirebilir.

Fail-safe mekanizmaları ise batarya voltajının düşmesi veya sensör verilerinde tutarsızlık oluşması gibi durumlarda devreye girer. Amaç, İHA'yı güvenli bir moda geçirerek hasar görmesini önlemektir.

### ArduPilot ve PX4 Karşılaştırması

ArduPilot ve PX4, açık kaynaklı iki otopilot yazılımıdır. ArduPilot 2009, PX4 ise 2011 yılından beri geliştirilmektedir.

Videoda özellikle lisans farklılıklarına dikkat çekiliyor. ArduPilot üzerinde değişiklik yapılarak geliştirilen yazılım ticari bir üründe kullanıldığında, yapılan değişikliklerin açık kaynak olarak paylaşılması gerekebilir. PX4 ise ticari projelerde yazılımın kendi kodlarını korumaya daha fazla imkân tanıyan bir lisans yaklaşımına sahiptir.

ArduPilot, hobi amaçlı projelerde ve kendi İHA'sını geliştiren kullanıcılar arasında daha yaygın bir topluluğa sahiptir. Bu nedenle karşılaşılan sorunlara yönelik örnek ve çözüm bulmak daha kolay olabilir. PX4 ise daha küçük ancak aktif bir geliştirici topluluğuna sahiptir ve özellikle araştırma-geliştirme projelerinde tercih edilebilir.

ArduPilot genellikle Mission Planner, PX4 ise QGroundControl ile birlikte anılır. Ancak günümüzde iki yazılım da farklı yer kontrol istasyonlarıyla kullanılabilir. Hangi yazılımın seçileceği projenin ihtiyaçlarına ve kullanım amacına bağlıdır.

### Multikopter ve Sabit Kanat Uçuş Modları

Uçuş modları genel olarak manuel destekli, akrobatik ve otonom modlar şeklinde ayrılabilir.

**Position Mode:** Multikopterde IMU, barometre ve GPS verilerini kullanır. Pilot kumanda kollarını bıraktığında araç bulunduğu konumu korumaya çalışır. Rüzgâr nedeniyle yer değiştirse bile tekrar önceki konumuna dönmeye çalışır.

**Altitude Mode:** IMU ve barometre kullanılır ancak GPS'e ihtiyaç duymaz. Bu nedenle araç bulunduğu konumu sabitleyemez; fakat irtifasını korumaya çalışır. Kumanda bırakıldığında aracın yatay duruşunu düzeltmesine de yardımcı olur.

**Stabilize Mode:** Bu modda kontrol daha çok pilottadır. Otopilot aracın yatay duruşunu korumaya yardımcı olur ancak irtifa ve konum kontrolü pilota aittir. Örneğin multikopterde gaz verilmezse araç irtifa kaybedebilir.

Sabit kanatlı araçlarda ise sürekli ileri hareket gerektiğinden position ve altitude modlarının uygulanışı farklıdır. Position modunda araç GPS yardımıyla belirli bir yönde ve rotada ilerlemeye devam eder. Altitude modunda ise GPS olmadan irtifayı ve yatış kontrolünü korumaya çalışır.

**Mission Mode:** Önceden hazırlanan uçuş planının otomatik olarak gerçekleştirilmesini sağlar. Kalkış, belirlenen noktaların takip edilmesi ve iniş bu plan içerisinde tanımlanabilir. Sabit kanatlı araçlarda iniş öncesinde pistle hizalanmak için loiter adı verilen dönüş hareketi yapılabilir. Multikopterlerde ise araç iniş noktasına gelerek doğrudan alçalabilir.

**Hold Mode:** Bekleme modu olarak kullanılır. Multikopter bulunduğu konumda sabit kalmaya çalışırken sabit kanatlı araç bulunduğu noktanın çevresinde daire çizerek uçabilir. Bir sorun yaşandığında aracı beklemeye almak ve ardından başka bir moda geçmek için kullanılabilir.

**Return Mode:** İHA'nın belirlenen home position noktasına geri dönmesini amaçlar. Özellikle aracın geri çağrılması gerektiğinde kullanılır.

**Takeoff ve Land:** Kalkış ve iniş işlemlerini gerçekleştirmek için kullanılan modlardır.

### Offboard Mode

Offboard Mode, uçuş kontrolcüsünün hareket komutlarını harici bir sisteme bıraktığı özel bir moddur. Bu sistem genellikle Raspberry Pi veya Jetson gibi görev bilgisayarları olabilir. Görev bilgisayarı ROS veya MAVLink üzerinden uçuş kontrolcüsüne komut gönderebilir.

Bu modda yalnızca belirli bir noktaya gitme komutu değil, hız, ivme, gövde açısı, yaw ve doğrudan itki gibi farklı kontrol değerleri de gönderilebilir. Böylece İHA üzerinde daha ayrıntılı ve özel hareketler gerçekleştirilebilir.

Offboard Mode özellikle engelden kaçınma, görsel konumlama ve birden fazla İHA'nın birlikte yönetilmesi (swarm) gibi uygulamalarda kullanılabilir.

Ancak bu modda görev bilgisayarından gelen komut akışı kesilirse araç kontrolsüz kalabileceği için PX4 fail-safe mekanizmasını devreye sokabilir. Ayrıca gönderilen komutların aracın güvenli uçuş sınırlarını aşmaması gerekir. Örneğin sabit kanatlı bir araç fazla dik tırmandırıldığında hızını kaybedebilir ve kaldırma kuvvetini kaybederek düşebilir. Bu nedenle PX4, güvenli olmayan bazı komutların uygulanmasını engelleyen kontroller de bulundurur.

### Genel Değerlendirme

Bu eğitim serisinde İHA'ların temel yapısından başlayarak motorlar, ESC'ler, uçuş kontrolcüleri, sensörler, telemetri ve görev bilgisayarları gibi bileşenlerin görevleri ele alındı. Ayrıca görüntü aktarımı ve yer kontrol istasyonlarının sistem içerisindeki yeri incelendi.

Yazılım tarafında ise ArduPilot ve PX4'ün çalışma mantığı, uçuş modları ve görev bilgisayarlarıyla haberleşme konuları öğrenildi. Bu konular birlikte değerlendirildiğinde bir İHA'nın yalnızca motor ve pervanelerden oluşmadığı; sensörlerden gelen verileri işleyen, karar veren, haberleşen ve uçuşunu kontrol eden birçok bileşenin birlikte çalışmasıyla görev yaptığını görmek mümkün oluyor.
